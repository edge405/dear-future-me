# Live acceptance checklist

Run after authenticated deployment, both remote migrations, secrets, channel verification, and webhook registration. Use harmless sample content. Automated tests mock Telegram/Gemini and cannot certify real channel visibility, actual project billing eligibility, provider quota, or production CPU time.

1. **Routing/security:** GET `/health` returns only service/ok. Unauthenticated POST `/telegram/webhook` returns 403. From another Telegram account, `/history`, `/journal`, and attempted bot callbacks reveal nothing. Add no real journal content from a group; group actions must be ignored. Never share the webhook secret to test this.
2. **Owner onboarding:** Send `/start`, `/help`, `/id`, `/settings`, `/privacy`, `/today`. Confirm your numeric owner ID, AI off, and 7 PM Manila schedule. The bot should respond only in your private conversation.
3. **Collection:** `/journal`; send two separate short notes (include English/Tagalog/Ilonggo if applicable), a single photo with caption, a multi-photo album, video with caption, voice recording, audio file, and document. Keep originals. `/status` should count every accepted message. No content should yet appear in the channel.
4. **Resume:** Send `/journal` again; verify the same draft/message count. `/save` before `/done` must ask for preview and publish nothing.
5. **Preview and edits:** `/done`; inspect all pages and verify original wording/captions, date, album count, and no transcription claim. Edit an original note or add a note. The old Save button must be rejected. `/done` produces a fresh preview.
6. **Approval/save:** Wait for all album items; read through the final preview page. Choose Save Original or `/save original`. Tap Continue Save if shown. Check dated heading, original text story, separately copied originals, correct ordering, captions, album grouping, video, playable voice/audio, and document. Compare text/spacing/entities to your source messages. Confirm the bot sends the correct private-channel link and it opens for your owner account.
7. **Idempotence/history:** Repeat `/save`, inspect `/history` and `/today`. They must link to the same archive with no new channel posts. Inspect D1 with a metadata-only query to confirm published status and cleared temporary fields; avoid dumping unfinished text into logs.
8. **Backdating/cancel:** Select an unused past `/date YYYY-MM-DD`, write a note, `/cancel`, and choose Keep Writing. Then `/cancel` and explicitly confirm; no channel posts should appear. Start that date again and confirm a fresh empty draft. A future date or impossible date must be rejected.
9. **AI optional:** Keep AI off and confirm ordinary archiving works. If you separately verified a billing-disabled free project, run the synthetic setup probe, deploy AI configuration, and use `/ai_on`. No personal text should reach Gemini until you tap the consent button. Test English-only, Tagalog-only, and Taglish notes, each spread across multiple messages. `/done` should show one factual title and one continuous first-person paragraph in the original language, without a separate reflection, question, or summary. Compare people, events, amounts, times, feelings, and uncertainty to the originals. Check that neutral transitions do not invent causes. Test an English `/revise improve the transitions and keep my wording` request on Tagalog/Taglish notes; it must not translate the story. Test bounded Regenerate, stale-button rejection, and Save Original. Approved channel output should have a dated heading, bold title, paragraph, then untouched originals/media. `/ai_off` must prevent later requests and invalidate unused consent buttons. Use a deliberately invalid test key only on a separate test deployment to test original fallback; do not disrupt a real daily draft unnecessarily.
10. **Recovery:** Use a separate harmless test draft. Remove bot posting permission before saving to test a definite error; restore permission, run channel verification, then retry. Completed operations must remain once. Simulated lost response/partial-copy mapping is automated; live ambiguous results, if encountered, must follow RECOVERY.md. Do not deliberately delete meaningful originals to test failure.
11. **Reminders:** Check the deployed cron `0 11 * * *` and Asia/Manila date. On an unsaved day, `/reminder` can explicitly test delivery; repeating it must not duplicate the reminder. That consumes today's reminder slot. To test the automatic schedule, leave a different day unsaved and wait around 7 PM Manila with the bot unblocked; your computer may be off. A saved day must skip the reminder. Inspect metadata if delivery was uncertain.
12. **Free-plan operation:** Confirm Workers Free and no added paid services. Check real CPU/request/D1 usage during a typical journal and a longer one, especially first-use isolates. If free limits interrupt the workflow, preserve originals and investigate within Free; do not upgrade. Confirm no logs contain journal bodies or secrets.

Local cron development: `npm run dev` exposes Wrangler's scheduled test route. With safe test credentials and local D1 only, use `http://localhost:8787/__scheduled?cron=0+11+*+*+*&time=UNIX_MILLISECONDS_AT_11_UTC`. Use an 11:00 UTC scheduled timestamp within the last hour; the handler intentionally ignores stale/mismatched slots. The synthetic automated reminder tests do not require any real Telegram request.

Acceptance remains pending until every applicable live step is verified by the operator. Image analysis, transcription, and historical AI retrieval are deliberately outside this release.
